## 2026-07-02 - Expensive SFU Usage in GLSL Adhesion Calculations
**Learning:** The use of `pow(abs(x), -2)` in shader code (like in `shaders/lib/pbr/material.glsl`) is a common anti-pattern that triggers highly expensive Special Function Unit (SFU) evaluations via `exp2(-2 * log2(abs(x)))`. This bottleneck is specific to GPU architectures where ALU operations are significantly faster than SFUs. Furthermore, using integers (`0`, `1`) instead of floats (`0.0`, `1.0`) causes implicit casting overhead.
**Action:** Always replace `pow(abs(x), -2)` with the mathematically identical, native ALU operation `1.0 / (x * x)`. Additionally, cache intermediate values (like dot products) to avoid redundant calculations, and strictly use float literals to prevent implicit casting overhead and potential compilation errors on stricter GLSL compilers.
