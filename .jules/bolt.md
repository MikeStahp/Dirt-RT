## 2024-05-18 - Avoid Trigonometric Functions in Hash Implementations
**Learning:** In GLSL shaders, using trigonometric functions like `sin`, `cos`, `tan`, and `atan` within frequently called hash functions (e.g., `hash(float)`, `hash12`, `hash13`, `hash14`) causes significant Special Function Unit (SFU) bottlenecks. This happens because these transcendental operations are computationally expensive compared to standard arithmetic logic unit (ALU) operations. For example, the `noised` function calls `hash(float)` eight times per invocation, making the overhead massive if `hash(float)` relies on `cos()`.
**Action:** Always prefer pure ALU-based hash functions (like Dave Hoskins' method) over trigonometric ones. When modifying or reviewing utility functions in GLSL, ensure that `hash` functions strictly use ALU operations (e.g., making generic `hash(float)` an alias for ALU-based `hash11(n)`).
