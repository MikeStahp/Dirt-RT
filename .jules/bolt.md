## 2024-05-24 - Avoid Trigonometric Operations in GLSL Hash Functions
**Learning:** Using trigonometric functions (`tan`, `atan`, `cos`) in heavily-called GLSL hash functions (like `hash12`, `hash13`, `hash14`, and `hash(float)`) causes significant Special Function Unit (SFU) bottlenecks, especially when used within noise generation (e.g., `noised` calls `hash` 8 times) and Fractal Brownian Motion evaluations (e.g., `fbm3D` calls `noised` multiple times). Pure ALU-based methods (like Dave Hoskins' hash implementations) avoid this overhead.
**Action:** Always prefer ALU-based operations for hash functions in GLSL shaders instead of relying on `sin`, `cos`, `tan`, or `atan`. Replace any occurrences of these trig functions in utility code to prevent performance regressions.
