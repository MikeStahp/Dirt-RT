## 2026-05-01 - GLSL Hash Function Optimization
**Learning:** Certain GLSL hash functions (`hash12`, `hash13`, `hash14`, and `hash(float)`) were regressing to expensive trigonometric operations (`tan`, `atan`, `cos`) instead of using pure ALU-based operations (like Dave Hoskins' method). This causes significant Special Function Unit (SFU) bottlenecks, especially when used in high-frequency paths like FBM or noise generation. Additionally, redundant or duplicated functions (`fasthash13`) can create maintenance burdens if they don't delegate to the optimized base implementations.
**Action:** Replace trig-based hash operations with pure ALU-based math. Ensure wrapper functions like `fasthash13` act as direct aliases (e.g., `return hash13(p3);`) and generic wrappers like `hash(float)` delegate to optimized versions like `hash11(n)`.
