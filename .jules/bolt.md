## 2024-05-24 - [Avoid Trigonometric Functions in Frequent Shaders]
**Learning:** In GLSL shaders for Vulkanite path tracing, using trigonometric functions like `cos`, `tan`, or `atan` in low-level, frequently invoked functions (e.g., hash functions used by noise generators like `noised` and `fbm3D`) causes significant performance bottlenecks due to Special Function Unit (SFU) overhead. The `hash(float)` function in `shaders/lib/common/hash.glsl` was using `cos`, which is very expensive when called 8 times per `noised` invocation and up to 40 times per `fbm3D` invocation.
**Action:** Prefer pure ALU-based hash functions (like Dave Hoskins' `hash11`, `hash12`, etc.) over those relying on trigonometric operations, especially in critical paths. Replace `fract(cos(n) * 41415.92653)` with a direct call to the already available ALU-based `hash11(n)` for immediate performance gains.
