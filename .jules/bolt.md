## 2024-05-18 - [Optimization] Pure ALU Hash Functions over Trigonometric Operations
**Learning:** In GLSL shaders, relying on trigonometric functions (`tan`, `atan`, `cos`, `sin`) inside fundamental math functions like PRNGs (hashes/noise) introduces severe performance bottlenecks because these operations consume Special Function Unit (SFU) cycles. This becomes particularly critical in iterative functions like `noised()` or `fbm3D()` that call `hash()` multiple times per invocation.
**Action:** Always prefer Dave Hoskins' pure ALU-based approaches for hash and random number generation inside shaders. Alias simple hashes like `hash(float)` to ALU versions like `hash11(n)` instead of employing mathematical functions like `fract(cos(n) * K)`. Check heavily used functions for hidden SFU costs.
