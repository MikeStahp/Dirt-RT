## 2024-05-18 - [ALU over Trig in GLSL Hash Functions]
**Learning:** The previous implementation of hash functions (e.g., `hash12`, `hash13`, `hash14`) in `shaders/lib/common/hash.glsl` utilized expensive trigonometric operations like `tan` and `atan`. These trigger heavy usage of the Special Function Units (SFU) in the GPU, causing slowdowns, especially inside tight loops used for noise generation where these functions are repeatedly evaluated.
**Action:** Always prefer Dave Hoskins' pure ALU-based hash generation (which uses purely arithmetic operations like `fract`, `dot`, `*`, `+`) instead of involving trigonometric functions. This change eliminates the SFU bottleneck in performance-critical paths. I have updated the hash functions to use ALU logic, optimizing the heavy noise-related operations.
